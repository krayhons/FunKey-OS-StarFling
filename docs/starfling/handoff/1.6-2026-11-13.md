223 ms -> video subsystem 185 ms -> `FB_OpenKeyboard` 189 ms ->

mark after `game exec`).

## Where the 1.951 s goes now (median, boots 304-308)

kernel 0.50 | rcS 0.50 (S10share 226 ms) | profile/frontend 0.20 |
exec -> main 231 ms | main -> config 67 | config -> SDL 89 | SDL -> splash
~0.25 | splash -> menu ~0.35 (fonts 46 ms, layout 30, Main collection 59,
menu built -> first frame ~50).

**exec -> main (231 ms) is SD-bound, not CPU-bound** (found after the
first version of this note): a 10 ms CPU sampler (boots 318-319, tool in
`~/sfwork/sampler/`, not in the repo) shows RetroFE mostly in state D.
Preloading its libraries at rcS start cut the step to 44 ms but delayed
everything before it by the same amount (menu unchanged, boots 321-325):
the boot is bound by total SD reads (high-speed mode, 25 MB/s max, no
UHS on this board). Levers: read less (smaller binaries/libraries, only
needed pages), or overlap reads with CPU-only work. #28 is the cheap
scheduler part. Earlier reasoning, kept for reference:
 `retrofe --version`
(loads all 14 libs, exits) takes 60 ms with a cold page cache, 30 ms
warm. Something else holds the single core in that window. Next step:
find what (ftrace `sched_switch`, or a bootchart boot). Candidates seen
in `/proc/*/stat`: fkgpiod (590 ms CPU over 87 s), the `spi0` fbtft
thread (1360 ms over 87 s, i.e. frame pushes), starfling-audio-init
(alsactl restore runs 1.50-1.59 s).

## Pitfalls hit

- `git format-patch`/`git am` between the 22.04 build clone and the
  push clone strips the CRLF of RetroFE patches -> CI "Apply the patch
  series" fails ("different line endings"). Copy patch files byte for
  byte instead. Force-push is blocked by the auto-mode classifier; fixed
  with follow-up commits on #24/#25.
- busybox `cp` has no `-n`: a "backup if missing" silently did nothing
  and the device's SDL was overwritten by a marked build. Recovered the
  original from the CI image's `rootfs.ext2` with `debugfs dump`.
- A temporary RetroFE build with a `getrusage`/`/proc/stat` mark at
  `main` crashed right after `main`; the frontend restarted it every
  0.65 s for the whole round (boots 310-312 are garbage). Not
  investigated; restored the good binary.
- `make FunKey/<pkg>-rebuild` keeps edited sources (good for temporary
  marks); `-dirclean` before building a real patch. RetroFE's build dir
  was dircleaned at the end.
