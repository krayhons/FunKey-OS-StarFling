### #16: why the notice did not clear

`notif set` started its clear timer (`notif display N msg &`) in the
caller's session. When the caller's terminal hangs up while the timer
sleeps (an adb shell exiting, e.g. `share start` run over adb), the timer
gets SIGHUP and the text stays until the next notification. Run from
RetroFE's quick menu it clears (K confirmed). Reproduced on the device:
caller sent SIGHUP 1 s after `notif set 4` → still on screen at 6.2 s;
with `setsid` it clears on time. `trap '' HUP` does **not** work: busybox
ash resets ignored traps in a forked background child (SigIgn had no
SIGHUP bit).

### Kernel: `initcall_debug` boot (task 1.5 groundwork)

One boot with `initcall_debug log_buf_len=256K` added to `args_mmc` via
`fw_setenv` (restored afterwards; backup of the original value in
`/mnt/starfling-orig/args_mmc.orig`). dmesg copy: not in the repo.

- Initcalls sum to 535 ms; root is mounted at 0.593 s.
- Largest: fbtft (ST7789V) 145 ms (`mdelay(120)` after SLPOUT + `mdelay(5)`
  after reset, busy-waits), pwm_backlight 76 ms (no messages; cause
  unknown, PWM and regulator code have no long delays), OHCI 72 ms + EHCI
  28 ms (USB host), sunxi-mmc 56 ms, deferred probe 36 ms (AXP power
  supplies ~30 ms, MUSB 4 ms), I2C/AXP 23 ms, UART console 21 ms.
- **The critical path is the SD card, not the initcall list.** MMC probes
  at 0.297 s, the card is ready at 0.566 s, root mounts at 0.593 s; the
  initcalls end at 0.553 s. Making fbtft async alone saves only ~50 ms.
  The lever is to probe MMC earlier (before pwm_backlight, USB host, UART)
  and/or make those probes async, then fbtft async with `msleep`.
- Kernel patches would go in `FunKey/board/funkey/patches/linux/`
  (`BR2_GLOBAL_PATCH_DIR`). Kernel and DTB ship in the `.fwu`.
- Kernel test boots were **not** done: a kernel that does not boot needs K
  (Recovery + `.fwu`). Do them with K present.

## Decisions made this chat (and why)

- `setsid` for the notif timer, not `trap '' HUP` (does not survive
  busybox ash's fork) and not a RetroFE change (RetroFE's path works).
- #17 keeps the GStreamer/GLib packages installed: only RetroFE stops
  loading them; dropping the packages is a separate size question.
- Game autoround: write `/mnt/instant_play` by hand in `instant_play
  save`'s format instead of asking K for another power cycle. The game
  starts fresh (no savestate), which DEVLOOP already accepts for timing up
  to "game exec". Do not start a game round with a plain `reboot` while a
  resumed game runs: picoarch dies, `instant_play` deletes `resume_play`,
  and the round boots to the menu.

## Pitfalls hit (for the next agent)

- `gh` and push credentials are only in the default WSL distro
  ("Ubuntu"), not in Ubuntu-22.04 (this session ran inside 22.04). Run
  `gh`/`git push` there via
  `wsl.exe -d Ubuntu --cd /home/krayhons -- bash -ls` with the script on
  stdin; it has its own clone at `~/FunKey-OS-StarFling`.
- The session scratchpad under `/tmp/claude-1000/...` was wiped between
  commands; working files went to `~/sfwork` instead.
- `pkill -f "notif display"` (in `notif set`) and `pkill -f <pattern>` in
  general match any shell whose command line contains the pattern,
  including your own adb or Bash command. Use `[n]otif` style patterns.
- Injecting keys by writing to `/dev/input/event0` worked for a few
  presses, then RetroFE stopped reacting to them; physical buttons were
  fine. Not reliable for automation.
- `fbgrab` and `/dev/fb0` only show back buffer 0, often not what is on
  screen.
- `.fwu` updates reset the theme to RetroRoomCovers (`layout.conf` lives
  on the rootfs). Re-set it before timing (theme changes the menu time by
  ~90 ms).
