## Decisions made this chat (and why)

- Autoround (#7) so the agent can measure without adb; warm reboots
  validated against K's cold boots.
- Amp warm-up with `tinyplay`, not `aplay`: alsa-lib config parsing cost
  ~75 ms of early boot vs ~40 ms.
- Audio order: warm-up first, then restore, then volume. A restore after
  the amp is up does not re-trigger the 700 ms sleep (measured: RetroFE's
  SDL step stayed ~130 ms). A ready flag, because `tinyplay` holds the PCM
  device and gpsp opens the hardware device directly (EBUSY → the resumed
  game exits).
- Gadget setup delayed 3 s: started immediately, even at nice 19, it
  slowed the following scripts (module load and USB enumeration run in the
  kernel at normal priority).
- S49audio, S52audioinit kept on the boot path until task 1.5a (USB-C
  audio routing).

## Tried and rejected

- **Prefetching RetroFE and its 22 libraries** (`cat` to /dev/null from
  inittab after `mount -a`, skipped on Instant Play). exec → `main` fell
  from 395 to 58 ms, but every earlier stage slowed by the same amount
  (rcS end 1.19 → 1.57 s, S01 40 → 131 ms): early boot is SD-bound too, so
  prefetching only reorders reads. Menu unchanged at 2.784 s (n=5).
  Fewer bytes read is the lever (e.g. drop RetroFE's unused GStreamer
  linkage, ~2.7 MB of ~10 MB; squashfs in gated 1.9).

## Pitfalls hit (for the next agent)

- `adb push` from Windows creates files **without the execute bit**; always
  `chmod 755` pushed scripts. A non-executable `starfling-audio-init` looked
  like a deterministic early-boot race for a while.
- `ps` on the device is procps-ng: without `-e` it lists only the caller's
  terminal. Use `ps -e`.
- Replacing a running binary/script leaves the old inode open; `ro` then
  reports "/ is still read-write" (correctly). Reboot cleanly.
- `kill` (TERM) on picoarch saves and powers off (Instant Play); use
  `kill -9` to get back to the menu without saving.
- Buildroot strips target binaries only at finalize; strip a
  `make <pkg>` binary (`host/bin/arm-linux-strip`) before pushing it for
  timing.
- Local `rm -rf` on variable paths is blocked by Claude Code's safety
  check; write results to fresh directories instead.
